# AstraAudit

**AstraAudit** — бесплатный инструмент командной строки для автоматизированной проверки базовых настроек безопасности **Astra Linux**. Он написан на Python, запускается локально, не требует `pip` и не изменяет конфигурацию системы.

[![Tests](https://github.com/ztfy404/AstraAudit/actions/workflows/tests.yml/badge.svg)](https://github.com/ztfy404/AstraAudit/actions/workflows/tests.yml) ![Python](https://img.shields.io/badge/Python-3.7%2B-blue) ![License](https://img.shields.io/badge/license-MIT-green) ![Status](https://img.shields.io/badge/status-beta-orange)

> **Статус: beta (v0.1.0).** Программа проверена автоматическими тестами в Linux, но ещё не испытана на реальной Astra Linux 2.12. Это **первичный аудит конфигурации**, а не полноценный пентест и не подтверждение соответствия требованиям ФСТЭК, ГОСТ, CIS или других стандартов.

## Что делает

AstraAudit выполняет **47 локальных проверок в 10 категориях**, классифицирует результаты и формирует **JSON, Markdown и HTML**-отчёты. Проверяются настройки пользователей, файловых прав, SSH, ядра, сети, аудита, журналирования, пакетов и отдельных средств защиты. Сетевые запросы и автоматическое исправление обнаруженных проблем **не выполняются**.

### Быстрый старт на Astra Linux

Открой терминал непосредственно в Astra Linux либо подключись к ней по SSH:

```bash
# 1. Проверь наличие Python и Git
python3 --version
git --version

# 2. Если Git или Python отсутствуют, установи их из настроенного репозитория Astra
sudo apt update
sudo apt install -y python3 git

# 3. Скачай проект
git clone https://github.com/ztfy404/AstraAudit.git
cd AstraAudit

# 4. Проверь список доступных проверок
python3 audit.py list

# 5. Запусти аудит
python3 audit.py run
```

**Более полный аудит** с доступом к системным данным (инструмент по-прежнему ничего не исправляет):

```bash
sudo python3 audit.py run --output /tmp/astraaudit-reports
```

**Результат:** в консоли появятся статусы по каждой проверке, а в конце — пути к файлам отчётов. Если запускать через `sudo`, созданные файлы могут принадлежать `root`.

## Команды

| Команда | Назначение |
|---|---|
| `python3 audit.py run` | Выполнить все проверки |
| `python3 audit.py list` | Показать идентификаторы и категории проверок |
| `python3 audit.py version` | Показать версию |
| `python3 audit.py run --category ssh` | Проверить только настройки SSH |
| `python3 audit.py run --category kernel --category network` | Проверить ядро и сеть |
| `python3 audit.py run --format html` | Создать только HTML-отчёт |
| `python3 audit.py run --format json,md,html --output ~/audit-results` | Выбрать форматы и папку для отчётов |
| `sudo python3 audit.py run --output /tmp/astraaudit-reports` | Запустить с расширенными правами чтения |
| `python3 audit.py run --strict` | Вернуть код завершения `2`, если есть `FAIL` |
| `python3 -m unittest discover -s tests -v` | Запустить тесты самого проекта |

### Какие параметры проверяются

| Категория | Примеры проверок |
|---|---|
| `system` | ОС, свободное место, umask, наличие LUKS |
| `identity` | UID 0, пустые хэши паролей, NOPASSWD, политика сроков паролей |
| `permissions` | Права на `/etc/passwd`, `/etc/shadow`, `/etc/sudoers`, конфигурацию SSH |
| `kernel` | ASLR, защищённые ссылки, ограничение `dmesg`, BPF |
| `network` | SYN cookies, ICMP redirects, IP forwarding, firewall, TCP listeners |
| `ssh` | Доступность SSH, root login, пустые пароли, парольный вход, MaxAuthTries |
| `logging` | auditd, правила аудита, journald, syslog, logrotate |
| `packages` | Состояние dpkg, кэш обновлений APT, протокол репозиториев |
| `security_modules` | LSM, AppArmor, признаки PARSEC, синхронизация времени |
| `applications` | Открытые порты БД, права конфигурации БД, Docker socket |

Полный актуальный список и идентификаторы:

```bash
python3 audit.py list
```

## Как читать результат

Пример вывода (только иллюстрация, **не результат проверки Astra**):

```text
AstraAudit 0.1.0 | 5 checks | read-only | no network requests
[INFO] SSH-01   SSH service inventory
[PASS] SSH-02   Disable root SSH login
[PASS] SSH-03   Disallow empty SSH passwords
[WARN] SSH-04   SSH password login policy
[PASS] SSH-05   SSH authentication attempt limit
Results: PASS=3, WARN=1, FAIL=0, INFO=1, SKIP=0
Report: /home/user/AstraAudit/reports/astraaudit-....json
```

- **PASS**: установленная проверкой конфигурация соответствует принятому базовому правилу.
- **WARN**: следует изучить настройку; это не обязательно уязвимость.
- **FAIL**: выявлено явное нарушение конкретного правила проверки.
- **INFO**: справочная информация, без оценки безопасности.
- **SKIP**: проверка недоступна или недостаточно прав; **не** означает безопасный результат.

Процент успешных проверок относится только к реально оценённым правилам (`PASS`, `WARN`, `FAIL`). Это **не процент защищённости ОС**.

## Где лежат отчёты

По умолчанию программа создаёт папку `reports/` в текущем каталоге. Для каждого запуска генерируются три отдельных файла с уникальным именем:

```text
reports/
  astraaudit-YYYYMMDD-HHMMSS-xxxxxx.json
  astraaudit-YYYYMMDD-HHMMSS-xxxxxx.md
  astraaudit-YYYYMMDD-HHMMSS-xxxxxx.html
```


Права на новые файлы устанавливаются `0600` (чтение и запись владельцу). Новая папка создаётся с правами `0700`. **Не публикуй отчёты в GitHub без проверки**, даже если инструмент не собирает пароли, IP-адреса или полные пользовательские списки.

Для просмотра HTML-отчёта открой сгенерированный `.html` в браузере или перенеси файл на свой компьютер. Публиковать его не требуется.

## Безопасность и ограничения

- Используется только **чтение** настроек и запуск локальных диагностических команд. Нет попыток эксплуатации, перебора паролей, сканирования чужих сетей, изменений `sysctl`, установки пакетов и перезапуска служб.
- Инструмент не подключается к внешним серверам и не отправляет собранные данные.
- С `sudo` видны некоторые дополнительные параметры; запускай с повышенными привилегиями только после ознакомления с исходным кодом.
- Некоторые правила зависят от назначения узла: например, IP forwarding допустим для маршрутизатора, а авторизация по паролю может применяться по политике организации.
- Проверка наличия LUKS не доказывает шифрование корневого раздела; обнаружение PARSEC не подтверждает корректность политики мандатного доступа.
- Отдельные параметры OpenSSH зависят от `Match` и контекста подключения. Программа не анализирует каждую такую комбинацию.
- Список обновлений APT берётся из **локального кэша**. Сетевую проверку новых версий программа не выполняет.
- На Astra Linux Special Edition некоторые защитные механизмы требуют отдельной специализированной проверки, которой в v0.1.0 нет.

Подробности: [SECURITY.md](SECURITY.md).

## Если что-то не работает

**`python3: command not found`** — установи Python из официального репозитория Astra или проверь, какой Python доступен в системе.

**`git: command not found`** — установи пакет `git` либо скачай ZIP проекта через кнопку **Code → Download ZIP** на GitHub.

**`SKIP: Requires sudo`** — повтори аудит через `sudo`, если имеешь право на администрирование этой машины.

**`SKIP: sshd -T unavailable`** — сервер OpenSSH не установлен, не доступен или его конфигурация не прошла проверку. Если SSH не нужен на этом узле, `SKIP` может быть нормальным результатом.

**Не удаётся сохранить отчёт** — укажи каталог, доступный для записи:

```bash
python3 audit.py run --output "$HOME/astraaudit-results"
```

**Не удалось установить пакеты через APT** — проверь `apt-cache policy python3 git`, доступность репозиториев и их настройки. Не подключай случайные репозитории Ubuntu/Debian к Astra Linux.
